# External Data Weighting Simulations: datasheet

Simulated classification problems in which a small in-domain labelled set is paired with an external pool
14 times larger, drawn from a shifted distribution. The tables hold the results of a benchmark on how much weight
the pool should get and how to choose that weight. Everything is synthetic. Nothing comes from real people or
real texts.

## Provenance and generation

The data are generated by the code in https://www.kaggle.com/code/locdunhat/how-much-weight-should-external-data-get.
The same package, `xdwbench`, is embedded in that notebook. Seeds are fixed (`SEED = 20261022`), so every file can be
regenerated exactly.

- 10 classes, 20 features. Class means are drawn so that the typical distance between two class means is 2 noise
  standard deviations. Each class has unit covariance.
- **In-domain and test rows:** Gaussian around the class means, with equal class counts.
- **Pool rows:** every class mean moves by `shift` times that typical distance, each class in its own random
  direction. Experiment 3 can also draw uneven pool class frequencies (Dirichlet(1)) and replace a share of the pool
  labels with random ones.

## Files

| file | rows | content |
| --- | --- | --- |
| `problems.csv` | 5 x (600 + 8,400 + 5,000) | one problem per shift level (0, 0.1, 0.25, 0.5, 1.0): `shift`, `split` (`in_domain`, `pool`, `test`), `label` (true class 0-9; for the pool, the label it was generated with), `x0`-`x19` |
| `exp1_curves.csv` | 2,100 | `n_in`, `shift`, `rep`, `method` (`mixture` with pool share `param`, `pool_only`, `two_stage` with pull `param`, `in_only` with ridge `param`), `acc` (test balanced accuracy) |
| `exp2_selection.csv` | 450 | `n_in`, `shift`, `rep`, `oracle_acc` (best fixed pool share on the test set), `method` (selection rule), `param` (its choice), `acc`, `cv_estimate` (the in-domain CV score of the chosen share, for `lam_in_domain_cv`) |
| `exp3_pool_quality.csv` | 80 | `pool_prior`, `label_noise`, `rep`, `weighting` (`class-balanced` or `raw`), `in_only`, `best_lam`, `best_acc`, `lam_cv`, `cv_acc` |

## Intended use

- Checking a weighting or domain-adaptation method against a known answer before using it on real external data.
- Teaching: why validating on pool rows picks too much pool, and why the best weight falls as in-domain data grow.

## Known limitations

- The model is linear and the classes are Gaussian. Real shifts are not a mean move per class, and a neural
  classifier fine-tuned in two stages behaves differently from the linear two-stage fit here. The direction of the
  effects is the point, not their size.
- The shift is the same size for every class. Real pools can be fine for some classes and far off for others.
- Test rows are in-domain and balanced, which is the setting of most competitions that ship a small train set.
